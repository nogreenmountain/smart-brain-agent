============================================================
一、功能简介
============================================================

AI Workday Monitor 用于汇总员工在 AgentOps 项目中的 AI 工作记录，
包括任务、Trace、Span、LLM 调用、工具调用、错误、Token、成本和延迟。

系统只读取 AgentOps 已有的 OpenTelemetry Trace 数据，不采集键盘、
鼠标、屏幕截图、剪贴板、浏览历史或其他桌面活动。

日报响应不会返回以下敏感原文：

1. Prompt 和 Completion 原文。
2. Tool 输入参数和输出结果。
3. 密钥、令牌和认证信息。
4. 完整文件内容和完整本地文件路径。

二、访问地址
============================================================

智慧大脑登录页：
http://192.168.1.40:3002/login

AI 工作日页面：
http://192.168.1.40:3002/workday

http://192.168.1.40:3001/traces

使用前请确认电脑能够访问服务器 192.168.1.40。


============================================================
三、登录与进入页面
============================================================

1. 使用浏览器打开：
   http://192.168.1.40:3002/login

2. 输入管理员分配的邮箱和密码。

3. 登录成功后，在左侧导航栏点击“AI 工作日”。

4. 如果左侧导航栏在移动设备上折叠为图标，请点击带日历/计时标记
   的“AI 工作日”图标。

注意：

- 用户只能查询自己是项目成员的项目。
- 仅属于同一组织、但没有加入项目成员列表的用户不能查看该项目日报。
- 非项目成员访问时，系统返回 403，并写入审计日志。


============================================================
四、生成 AI 工作日报
============================================================

进入“AI 工作日”页面后，按照以下步骤操作：

1. 选择项目

   从“项目”下拉框中选择要查询的 AgentOps 项目。
   下拉框只显示当前账号已经加入的项目。

2. 输入员工 ID

   在“员工 ID”中输入 Trace 上报时使用的员工聚合主键，例如：

   employee-001

   员工 ID 必须与 OpenTelemetry 属性
   agentops.employee.id 完全一致。

3. 选择工作日期

   在“工作日期”中选择需要生成日报的日期。
   日期按 Asia/Shanghai（北京时间）业务日解释。

4. 选择显示内容

   关键 Trace：
   开启后返回命中成本、延迟、错误或高工具调用规则的 Trace。

   Replay 链接：
   开启后为关键 Trace 显示“打开 Trace”链接。
   关闭“关键 Trace”时，Replay 链接会同步关闭。

   详细指标：
   开启后显示 Token 分类、模型使用和工具使用明细。

5. 点击“生成日报”

   页面显示“生成中”时请等待，不要连续重复点击。


============================================================
五、日报内容说明
============================================================

1. 工作概览

任务：
当天根据 agentops.task.id 聚合出的任务数量。

Trace：
当天符合员工和日期条件的 Trace 数量。

Span：
参与日报聚合的 Span 数量。

LLM 调用：
识别出的模型调用次数。

工具调用：
识别出的 Tool 调用次数。

错误：
状态为错误的 Span 数量。

Tokens：
Prompt、Completion、Reasoning 等 Token 的合计。

成本：
优先使用 Trace 上报的成本；没有上报时尝试根据模型和 Token 估算。

活跃时间范围：
最早有效 Span 到最晚有效 Span 的时间跨度。

LLM 平均延迟：
当天所有 LLM 调用耗时的平均值。

LLM P95 延迟：
95% 的 LLM 调用耗时不超过该数值，用于发现慢请求。


2. 确定性摘要

系统根据统计结果生成固定模板摘要，不调用 LLM，也不会改写统计事实。


3. 数据提醒

可能出现的提醒包括：

- Span 的 agentops.work.date 与请求日期冲突，该 Span 已跳过。
- Span 没有任务 ID，已归入 unassigned。
- 模型未找到价格，相关成本按 0 计算。
- 个别格式异常的 Span 已跳过。


4. 任务拆分

任务按照 agentops.task.id 分组，显示：

- 任务名称和任务 ID。
- 活跃时长。
- Trace 和 Span 数量。
- LLM 和工具调用数量。
- 错误数量。
- Token 和成本。
- LLM 平均延迟。

任务没有 agentops.task.id 时：

任务 ID：unassigned
任务名称：未标记任务

任务时长会合并重叠的 Trace 活跃区间，避免并行 Trace 重复计时。


5. Findings（发现）

系统按照确定性规则识别以下问题：

- 成本热点。
- Trace 成本异常。
- 延迟热点。
- 任务重复报错。
- 同一工具重复失败。

每条 Finding 包含严重程度、说明、阈值、实际值、任务 ID 和证据 Trace。


6. 关键 Trace

关键 Trace 会合并以下命中原因：

- cost_finding：命中成本规则。
- latency_finding：命中延迟规则。
- error_finding：命中错误规则。
- high_tool_usage：工具调用次数较高。

同一个 Trace 只展示一次，但可以包含多个命中原因。


7. 打开 Trace（Replay）

点击关键 Trace 右侧的“打开 Trace”后，浏览器会在新页面打开：

http://192.168.1.40:3001/traces?trace_id=对应的Trace ID

如果 AgentOps Dashboard 要求重新登录，请使用同一套 AgentOps 账号登录。


8. 蒸馏候选

蒸馏候选用于提示后续可能值得复盘或沉淀的结构化经验。

第一版只生成 status=pending 的候选，不会：

- 自动写入团队经验库。
- 自动给员工打标签。
- 自动修改项目记忆。
- 自动生成绩效结论。


9. 详细指标

Token 分类：

- Prompt Tokens。
- Completion Tokens。
- Reasoning Tokens。
- Cache Read Tokens。
- Total Tokens。

模型使用：

- 模型名称。
- 调用次数。
- Token 数量。
- 估算成本。

工具使用：

- 工具名称。
- 调用次数。
- 错误次数。


============================================================
六、无数据和错误处理
============================================================

1. 页面显示“暂无数据”

请依次检查：

- 项目是否选择正确。
- 员工 ID 是否输入正确。
- 日期是否选择正确。
- 当天是否已经上报 Trace。
- Trace 是否包含 agentops.employee.id。
- agentops.work.date 是否与查询日期冲突。

2. 页面显示 403 或“不是项目成员”

请联系项目 owner 或 admin，将当前账号加入 public.project_members。

3. 页面显示“生成日报失败”

请检查：

- API 是否可访问：http://192.168.1.40:8000/health
- ClickHouse 是否运行。
- AgentOps API 容器是否运行。
- 浏览器是否能够访问 8000 端口。

4. Replay 页面没有显示目标 Trace

请检查：

- URL 中是否保留 trace_id 参数。
- AgentOps Dashboard 是否已登录。
- Trace 是否仍保存在 ClickHouse 中。
- 查询账号是否有该项目的访问权限。

5. 成本显示为 0

可能原因：

- 调用方没有上报成本。
- 模型名称不在价格表中。
- Token 字段缺失。

此时请查看“数据提醒”中是否有未知模型价格警告。


============================================================
七、Trace 上报规范（开发人员）
============================================================

参与日报的 Span 应上报以下 OpenTelemetry 属性：

必填：

agentops.employee.id
说明：稳定的员工聚合主键。缺失时不进入员工日报。

建议填写：

agentops.employee.name
说明：员工显示名称；缺失时使用 employee.id。

agentops.task.id
说明：稳定的任务主键；缺失时归入 unassigned。

agentops.task.title
说明：任务显示名称。

agentops.work.date
说明：YYYY-MM-DD 格式的北京时间业务日期。

项目属性：

agentops.project.id
说明：AgentOps 项目 UUID，通常放在 ResourceAttributes 中。

后端优先读取 SpanAttributes，必要时兼容 ResourceAttributes。

LLM 识别建议使用：

gen_ai.operation.name
gen_ai.request.model
gen_ai.usage.prompt_tokens
gen_ai.usage.completion_tokens
gen_ai.usage.total_tokens
gen_ai.usage.total_cost

Tool 识别建议使用：

gen_ai.tool.name
tool.name
agentops.span.kind=tool
tool.status=error

本地样本脚本：

D:\AgentOpsServer\AgentOps\app\scripts\emit_workday_sample.py

开发契约文档：

D:\AgentOpsServer\AgentOps\app\agentops_local\workday\README.md


============================================================
八、权限与审计
============================================================

权限规则：

- 项目任意成员可以查看结构化 Workday 汇总。
- 非项目成员不能查看。
- 第一版不进行 employee_id 与登录 user_id 的本人映射。

审计 action：

workday_summary

审计信息包括：

- 查询用户。
- 项目 ID。
- 员工 ID。
- 工作日期。
- 三个 include 开关。
- 查询结果状态，例如 ok、no_data、forbidden、service_error。
- 查询时间和来源 IP。

审计日志不会保存 Prompt、Completion 或 Tool 原始内容。

============================================================
十、当前版本边界
============================================================

第一版暂不提供：

1. employee 独立数据表。
2. employee_id 与登录用户的本人绑定。
3. 周报和月报。
4. 自动写入项目记忆或团队经验库。
5. 自动蒸馏通过。
6. 员工绩效评价和员工标签。
7. 键盘、鼠标、屏幕或浏览器活动监控。

============================================================
